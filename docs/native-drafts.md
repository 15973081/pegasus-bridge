# 原生“保存”与命名草稿（0.13.0）

本功能对应天马工坊工具栏的 **保存 → 输入名称 → 确认**。编辑器内部称它为“备份”；这里用“原生草稿”区分本地 JSON 备份、玩家存档和发布草稿。

## 已实现

| CLI | MCP | 作用 |
|---|---|---|
| `list-drafts` | `pegasus_list_drafts` | 读取编辑器“打开 / 保存”窗口使用的备份列表 |
| `save-draft` | `pegasus_save_draft` | 将后台当前已保存内容创建为一份新的命名备份，随后读回列表核对 |

它使用编辑器保存窗口相同的备份接口，不模拟点击，不修改编辑器安装文件。在线操作需要自己的有效天马会话。它不要求窗口一直打开，但**不能强制提交编辑器内存里尚未同步的修改**。应先完成剧情/UI 保存并读回确认，再创建命名草稿。

## CLI 使用

```powershell
# 按自己的认证方式配置；此处显式使用本机已有的天马会话
$env:PEGASUS_ALLOW_LOG_AUTH = '1'
pegasus list-drafts 123456
pegasus save-draft 123456 "第一章_立绘完成" --checkpoint .\exports\draft-001.json
```

作品 ID `123456` 是占位值。名称限制为 1–100 个字符，不允许首尾空白或控制字符。已有同名草稿时拒绝创建，不覆盖旧条目。

`checkpoint` 为本地 `.json` 文件：新创建使用新路径，同一次创建的核对必须继续使用原路径。它记录作品、名称、创建前的备份 ID、请求状态和核对结果，不保存认证信息。

## MCP 使用

```json
{
  "game_id": 123456,
  "name": "第一章_立绘完成",
  "checkpoint": "C:/game/exports/draft-001.json"
}
```

将以上参数传给 `pegasus_save_draft`。`pegasus_list_drafts` 只需 `game_id`。当前服务共 **50 个 MCP 工具**；升级后需要重新连接客户端中的服务。

## 如何判断成功

成功时返回 `status: "verified"`、`complete: true`、`verified: true`，以及包含 `id`、`backupName`、`createTime` 的 `draft`。验证依据是服务端备份列表；没有声称已模拟点击或观察编辑器窗口。

重新打开编辑器顶部的“打开”窗口，会重新请求同一份备份列表。若列表窗口已经打开，应先关闭再打开，已有窗口不保证自动刷新。

如果创建响应丢失，工具会查询列表进行核对；如果仍无法确定，则返回 `complete: false`，CLI 退出码为 1。使用相同命令和检查点再次调用时，**只查询结果，不重发创建请求**。这样即使进程在请求后退出，也不会自动重复创建。

服务端没有可用的幂等键。没有返回 ID 时，核对依赖“创建前不存在、创建后只有一条同名备份”；若同时有人创建同名备份，不能完全确定创建者。请使用能区分任务的名称，避免多人同名操作。检查点保留了不确定结果时，不要直接换路径重试，应先核对原生列表。

## 协议依据与边界

本机已有的 `Editor.Core.dll` 反编译材料中，工具栏 `OnClickBackup` 打开 `ACBackUpView(false)`。窗口的 `RequestNodeList` 使用 `GET /avg-editor-api/game/{gameId}/backup`；确认时 `RequestCreateNodeFile` 序列化 `HttpBackup`，向同一路径发起 `POST`。新增对象只设置 `backupName`，其余数值为默认值。以上是本地静态分析依据，线上列表查询及成功创建则是运行证据。

分析对象 SHA256：`b4e951315fcd0924eed8162eca0ef641126eb68f52eace87270786e9a30af15a`。这些接口并非官方公开的稳定 API，可能随版本变化。

该版本只增加创建和列举，不提供删除、改名或恢复原生备份。备份创建与后续“打开备份”是不同操作：原生打开会替换当前作品数据，本次未执行，也未验收完整恢复范围。玩家存档、跨作品复制、发布草稿和公开发布均不属于此功能。
